## Findings · 问题

### Must Fix Now · 当前阻挡分发的问题

目前检查范围内未确认 P0 / P1（会造成普通启动失败、核心流程失效或直接泄露密钥的问题）。这只描述本轮证据，不代表所有使用环境均没有问题。

### P2 · 设置与密钥文件不是成对提交

- 影响：保存过程中，如果受保护的密钥文件已替换，而普通设置文件随后因文件占用、权限、磁盘问题或进程中断未完成替换，重启会提示文件版本不一致，需要重新填写连接密钥。
- 依据：`Settings/SettingsStore.cs` 的 `Save` 先写 `credentials.dat`，再写 `settings.json`；两个文件分别原子替换。`Load` 要求两者的 Revision 相同。
- 当前保护：读取不一致时不会把密钥降为明文；主窗口保留原文件并禁止自动覆盖，用户仍能重新配置。
- 建议：后续为两文件保存增加可恢复提交或上一版备份，并用“第二次写入失败”的故障注入测试验证恢复。此次审查没有修改存储格式。
- 等级说明：P2 表示非阻挡的正确性风险，失败条件在保存边界；已有重新配置的恢复办法。

### P2 · 多个程序实例可覆盖同一份设置

- 影响：重复打开 exe 会各自读取设置。若第二个窗口修改并保存后，第一个仍持有旧设置的窗口随后退出，它的保存会覆盖更新过的设置。
- 依据：`App.xaml.cs` 每次启动创建新的 `MainWindow`；没有实例互斥。`MainWindow.ClosingAsync` 对各自内存中的 SettingsBundle 调用 `SaveSettings`，保存目标是相同的当前用户目录。
- 当前使用办法：一次只打开一个主程序；修改连接设置后在同一个窗口继续使用。
- 建议：后续做单实例启动并激活已有窗口，或增加配置版本检查；需要“双实例修改后反向关闭”的回归检查。
